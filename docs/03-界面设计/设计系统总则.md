# 同庆云 UI/UX 设计系统总则

> **状态：** V1.0 候选基线，待完成真实 Vue 编译、MiSans 合法接入及视觉回归验收后冻结。
>
> **适用范围：** 平台 Web、商户 Web 及 Design Lab。移动端沿用设计语言，但按独立终端规范设计与验收。

## 1. 设计目标

同庆云面向连锁餐饮企业的多组织、高频运营与经营分析场景。设计系统应同时支持日常运营效率和经营决策，不以装饰性视觉牺牲信息密度、可读性或可操作性。

- **轻量现代：** 白色内容面板、浅灰工作画布、细边框与克制的圆角；默认不用渐变和重阴影。
- **业务清晰：** 蓝色只承载品牌、选中、链接、主操作与焦点；红、橙、绿只表示明确业务语义。
- **高效可用：** 以查询、表格、批量操作、表单和任务闭环为基本工作方式；信息密度优先但不牺牲可点击面积。
- **统一而有侧重：** 平台端偏治理与配置，商户端偏运营与经营决策；两端共享同一套 Token、组件、交互模式与质量门禁。

## 2. 设计体系边界与单一来源

| 范围 | 权威来源 | 约束 |
| --- | --- | --- |
| 色彩、字体、间距、尺寸、圆角 | `frontend/packages/design-tokens/` | 业务页面不得复制魔法值或形成第二套主题。 |
| Arco Design Vue 主题适配 | `frontend/packages/design-tokens/` | 集中维护；避免业务页面深度覆盖 Arco 内部样式。 |
| 公共业务交互组件 | `frontend/packages/ui-components/` | 查询面板、工具栏、状态面板、页头等必须复用。 |
| 可运行验收与视觉基准 | `frontend/apps/design-lab/`、自动化测试 | 未经人工批准，不以更新快照掩盖视觉变更。 |
| 本目录的中文规范 | `docs/03-界面设计/` | 记录设计决策、交互规则和验收范围。 |

## 3. 核心视觉与交互原则

- 使用品牌蓝 `#165DFF`、浅灰画布 `#F7F8FA`、白色面板、深灰文字与细灰边框；具体值以 Token 为准。
- 全局优先使用合法提供的 MiSans；未接入前使用系统安全回退字体，并不得声称完成字体验收。
- 默认控件高度为 32px，表格常规行高为 46px；查询控件使用自然宽度，禁止单一控件无上限撑满整行。
- 左侧导航为目录加叶子菜单的两级结构。目录使用 Arco 图标；二级菜单只用文字、无图标、无选中竖线，且文字与一级菜单文字起始位置对齐。
- 鼠标与键盘焦点应有可辨识的品牌蓝边框或轮廓，但不使用发光阴影。
- Loading、Empty、Error、No Permission 必须为不同状态；接口失败不得伪装为“暂无数据”。

## 4. 商户端体验定位

商户端是“高效运营工具”与“经营数据驾驶舱”的结合：运营功能帮助用户完成当天工作，经营数据帮助用户识别异常并采取行动。

### 4.1 运营首页（默认首页）

运营首页是登录后的默认工作台，不等同于完整经营驾驶舱。其内容按行动优先级组织：

1. 全局组织范围与日期范围，明确当前集团、区域、品牌或门店及数据口径。
2. 待办与预警，突出需处理的任务、异常和截止事项。
3. 常用运营入口，提供高频、已授权业务的快速进入方式。
4. 今日或当前周期核心指标，展示销售、客流、毛利等关键经营变化。
5. 精简趋势或异常榜单，提供“查看完整分析”的明确入口。

运营首页中的数据只用于快速判断和跳转，不承载复杂的多维分析配置。

### 4.2 完整经营驾驶舱（独立一级菜单）

完整经营驾驶舱面向区域经理、品牌负责人和集团经营人员，承载趋势、同比环比、组织对比、排行、预警归因与数据下钻。图表必须服务于可解释的经营问题，不制作脱离业务动作的装饰性大屏。

- 驾驶舱继承全局组织与日期范围，并明确指标定义、数据更新时间及适用范围。
- 指标、预警和排行应可进入带条件的明细页，例如异常门店进入门店经营明细，毛利异常进入商品或成本明细。
- 钻取后的列表保留来源条件；用户返回时保留驾驶舱筛选与滚动位置。
- 驾驶舱可使用更清晰的数据分层与留白，但不得引入第二套色彩、阴影或图表视觉语言。

## 5. 页面模板与验收

Web 端应以以下 Golden Page 为业务实现依据：标准列表、标准详情、标准新增/编辑、运营首页、完整经营驾驶舱、登录与身份入口。每个模板均须覆盖权限、加载、空数据、错误、禁用和键盘可达状态。

视觉验收至少覆盖 1280×900、1440×900、1920×1080 三种桌面视口。V1.0 冻结前必须完成真实依赖安装、类型检查、生产构建、关键交互测试与经人工批准的视觉基准。

### 5.1 登录与身份入口

- 登录页采用左侧品牌与产品能力展示、右侧居中认证表单的双栏布局；窄屏时品牌区域收束为简洁标题区，表单保持单列可访问。
- 左侧视觉只使用 Design System 的品牌蓝、白色与蓝灰透明层，采用代码原生的轻量经营工作台构图；可呈现经营分析、智能排班、智能申购、库存盘点等产品能力，但不得伪造真实经营数据或引入重型插画、第三方登录入口。
- 右侧表单按“标题、身份说明、字段、保持登录状态、主操作、帮助说明”顺序组织。输入框与主按钮采用 8px 圆角，主操作沿用品牌蓝；登录流程不得以视觉改版改变平台端和商户端的身份边界。
- 平台端使用平台运营账号；商户端必须保留五位商户号、商户组织账号与密码三个字段。两端均只提供账号密码登录，不展示登录方式切换或第三方登录。

## 6. 变更治理

调整主色、字号体系、导航结构、核心控件尺寸或图标库前，必须先记录设计决策并完成评审。确认后的变更应同步更新本目录规范、Token、公共组件、Design Lab 与视觉基准；未执行的验证必须如实登记。
