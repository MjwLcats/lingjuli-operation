# 商户端运营首页与经营驾驶舱规范

> **状态：** 已确认的 UI/UX 设计决策；实现与视觉基准验收仍待完成。

## 1. 决策结论

商户端采用“高效运营工具 + 经营数据驾驶舱”的双层体验，而不是在纯工具首页与纯数据首页之间二选一。

- **运营首页**是登录后默认首页：把待办、预警、常用运营功能和轻量经营概览放在同一页面。
- **经营驾驶舱**是独立一级菜单：提供完整分析、比较、排行、归因与下钻能力。

## 2. 信息结构

```text
商户端
├─ 运营首页（默认）
│  ├─ 全局组织与日期上下文
│  ├─ 待办与预警
│  ├─ 常用运营入口
│  └─ 轻量经营概览与异常入口
└─ 经营驾驶舱（一级菜单）
   ├─ 核心指标与趋势
   ├─ 组织/周期对比
   ├─ 排行与异常归因
   └─ 带条件下钻至业务明细
```

## 3. 运营首页规则

### 3.1 全局上下文

- 顶部统一提供当前组织范围与日期范围，范围可为集团、区域、品牌、业态或门店。
- 页面内业务筛选仅补充该页面特有的条件，不重复创建与全局上下文冲突的组织范围选择。
- 必须明确显示当前范围、数据口径和数据更新时间；无权访问的组织不得在前端以可选择状态出现。

### 3.2 内容优先级

| 优先级 | 区域 | 目标 | 典型内容 |
| --- | --- | --- | --- |
| P0 | 待办与预警 | 提示应立即处理的事项 | 待审批、待整改、同步失败、经营异常。 |
| P1 | 常用运营入口 | 缩短高频操作路径 | 商品、组织、任务、巡检等已授权模块。 |
| P1 | 核心指标 | 快速了解当日或当前周期经营状态 | 销售额、客流、毛利率、客单价及变化。 |
| P2 | 趋势与异常榜单 | 识别需进一步分析的问题 | 趋势摘要、异常门店、异常品类。 |

### 3.3 交互规则

- 待办、预警、常用入口均指向真实授权的业务页面；无对应能力时不展示伪入口。
- 指标卡和异常榜单的点击行为必须清晰：可点击项提供跳转语义，不能仅有装饰性 hover。
- 点击概览数据后，跳转到目标页面时必须携带组织、日期及必要业务筛选条件。
- 从明细返回时，保留首页范围和用户的页面位置。

## 4. 完整经营驾驶舱规则

- 驾驶舱优先回答“发生了什么、哪里异常、可能原因、下一步去哪里处理”四类问题。
- 每个指标必须有名称、统计口径、时间范围、组织范围和更新时间；必要时提供指标说明。
- 图表必须支持可理解的提示信息、图例和空/错状态。颜色按语义使用，不能仅以红绿区分而忽略色觉可访问性。
- 趋势、同比环比、组织对比、排行和异常归因可组合出现，但避免单屏堆叠无行动价值的图表。
- 下钻入口应到达筛选条件已预置的业务明细页；后端仍负责租户隔离与组织数据权限校验。

## 5. 视觉与响应式约束

- 运营首页和驾驶舱复用 Lingjuli Design System 的 Token、Arco Design Vue 组件和官方图标。
- 驾驶舱可增加合理留白和数据层级，不使用渐变背景、重阴影、夸张动效或新的品牌色。
- 桌面端以 1280px 及以上为主要工作场景；窄屏优先重排摘要区和入口区，宽表格与复杂图表在自身容器中处理滚动或降级，不让页面产生无控制的横向溢出。
- 移动端另行设计，不能将桌面驾驶舱简单等比例缩小。

## 6. 实现前验收清单

- [ ] 驾驶舱指标口径、更新时间与下钻目标已经产品确认。
- [ ] 组织与日期上下文在首页、驾驶舱和下钻页之间传递一致。
- [ ] 设计在 1280 / 1440 / 1920 宽度下完成视觉审核。
- [ ] 键盘焦点、图表替代说明与状态反馈满足可访问性要求。
